## 第一章：大模型是什么——一台文字接龙机器

在讲"训练"之前，必须先搞清楚被训练的东西是什么。它的底层机制不是"理解了问题然后思考作答"，而是<strong>玩文字接龙</strong>。

### 1.1 从文字接龙说起

给模型一段开头：`Today is a`。它做的事情是：把这三个词读一遍，然后对词表里<strong>每一个</strong>词打一个分，输出一个概率分布：

```text
输入: Today is a

模型输出（词表上每个词一个概率）:
  sunny    ████████████████████  0.62
  nice     ██████                0.18
  Monday   █████                 0.15
  banana   ▏                    0.0001
  ...      （词表里其余十几万个词）

选中 "sunny" 接上去 → 得到 "Today is a sunny"
再拿新句子预测下一个词 → 循环往复
```

一篇几千字的长回答，就是这样<strong>一个 token 一个 token 接出来的</strong>。每生成一个新 token，模型都要结合此前的上下文重新计算下一步概率；实际推理通常用 KV Cache 复用历史 token 的 Key/Value，避免把整段前文从头重复计算。

::: info

<strong>一个常见误解：</strong> 模型不是"想好了整段话再输出"，而是每一步只决定下一个词。前面接了什么词，会直接影响后面接什么词，所以同一个开头，接出的话每次都可能不一样。

:::

### 1.2 Token：模型眼中的文字

模型不直接处理字符，而是处理 <strong>token（词元）</strong>，即把文字切成的最小单元。切分由<strong>分词器（Tokenizer）</strong>完成，常用算法是 BPE（字节对编码）。

```python
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-7B")

tokens = tokenizer.tokenize("unbelievable power")
print(tokens)        # ['un', 'believ', 'able', ' power']

ids = tokenizer.convert_tokens_to_ids(tokens)
print(ids)           # [1036, 69507, 540, 1511]  ← 模型真正看到的是这些编号
```

- 英文常见词通常一个词一个 token，生僻词会被拆碎（如 `unbelievable → un + believ + able`）
- 中文大约 1 个汉字对应 1~2 个 token（取决于分词器）
- 计费、上下文长度限制，说的都是 token 数而不是字数：100 万 token 大约是 75 万英文单词

::: tip

<strong>为什么要有 token：</strong> 直接按字符处理，序列太长、计算太贵；直接按整词处理，词表会爆炸（中文组合无穷无尽）。token 是"长度"和"词表大小"之间的折中。

:::

### 1.3 Transformer：注意力加工厂

接龙的关键问题是：看到 `Today is a`，凭什么 `sunny` 的分数最高？因为模型读句子时，每个词都<strong>带上了上下文的信息</strong>。完成这件事的架构就是 <strong>Transformer</strong>（2017 年 Google 论文《Attention Is All You Need》提出）。先看整体结构：

```text
输入: "今天天气真好，我想吃"
   │
   ▼
┌─────────────────────────────────────────┐
│ ① Token 化 + 向量化                       │
│    文字 → 编号 → 每个词一个向量            │
│    （向量 = 一串数字，语义的数字表示）       │
└──────────────────┬──────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│ ② Transformer Block × N 层（N = 32~80+）  │
│  ┌───────────────────────────────────┐  │
│  │ 自注意力 Self-Attention             │  │
│  │ 词与词互相"对暗号"，谁重要就多抄谁的   │  │
│  │ 信息 —— 负责词之间的"沟通"            │  │
│  └───────────────┬───────────────────┘  │
│  ┌───────────────────────────────────┐  │
│  │ 前馈网络 FFN                        │  │
│  │ 对每个位置独立做非线性加工            │  │
│  │ —— 参与特征变换与知识表征              │  │
│  └───────────────────────────────────┘  │
│ （每层都有残差捷径 + 归一化，保证稳定）     │
└──────────────────┬──────────────────────┘
                   ▼
┌─────────────────────────────────────────┐
│ ③ 输出层：词表上每个词一个分数（logits）    │
│    "苹果 5.2 / 冰淇淋 4.8 / 书 3.1 ..."   │
└─────────────────────────────────────────┘
```

#### 1.3.1 为什么需要注意力

看这句话：`小猫追着球跑，它玩得很开心`。`它`指的是小猫还是球？人一眼就看出来是<em>小猫</em>（会"玩得开心"的是猫）。要让模型也能判断，`它`这个词的表示里就必须<strong>混入"小猫"的信息</strong>。

这就是注意力做的事：<strong>每个位置都会从允许访问的位置聚合相关信息</strong>。相关度越高，汇入的信息越多。在 Decoder-only 模型中，因果掩码只允许当前位置关注自己和更早的 token，不能看到未来。经过多层加工后，每个 token 的向量不再只表示它本身，还带有上下文信息。

#### 1.3.2 Q/K/V：词与词对暗号

注意力的具体机制靠三个矩阵，术语叫 Query、Key、Value。第一次见很容易被吓住，但用<strong>图书馆检索</strong>来理解就很简单：

<table>
<tr><th>角色</th><th>全称</th><th>含义</th><th>图书馆比喻</th></tr>
<tr><td><strong>Q</strong></td><td>Query（查询）</td><td>这个词<strong>想找</strong>什么信息</td><td>你写下的检索请求</td></tr>
<tr><td><strong>K</strong></td><td>Key（键）</td><td>这个词<strong>能提供</strong>什么线索</td><td>每本书贴的索引标签</td></tr>
<tr><td><strong>V</strong></td><td>Value（值）</td><td>这个词的<strong>实际内容</strong></td><td>书的正文</td></tr>
</table>

流程是：每个词拿自己的 Q，去和句中所有词的 K 做<strong>匹配打分</strong>（点积），分数经过 softmax 变成"注意力权重"（总和为 1），然后按权重把所有人的 V <strong>加权抄过来</strong>，加进自己的表示里。

```text
句子: "小猫 追 球， 它 开心"

处理 "它" 这个词时:
  "它"的Q × "小猫"的K = 8.1  ← 高分！
  "它"的Q × "球"的K   = 2.3
  "它"的Q × "追"的K   = 1.1
  ...
  softmax 后权重: 小猫 0.71 / 球 0.18 / 其他 0.11

  → "它"的新表示 = 0.71×小猫的V + 0.18×球的V + ...
  → "它"从此带上了"小猫"的信息，后面接龙就知道谁开心了
```

::: info

<strong>Q/K/V 怎么来的：</strong> 每个词的向量分别乘上三个可学习的矩阵 W_Q、W_K、W_V 得到。这三个矩阵就是模型要学的参数的一部分："怎么提问、怎么标索引、怎么存内容"本身是被训练出来的。

:::

#### 1.3.3 多头注意力

只从一个角度看句子不够。Transformer 让每个词同时发<strong>多组</strong> Q/K/V（比如 32 组，即 32 个"头"），每组独立做一遍注意力，最后拼起来。

不同的头会自发学会关注不同的关系：有的头盯着<strong>指代关系</strong>（"它"→"小猫"），有的看<strong>语法结构</strong>（动词找主语宾语），有的找<strong>相邻搭配</strong>。就像 32 个编辑同时从不同角度批注同一句话，最后汇总。

#### 1.3.4 位置编码

注意力有个先天缺陷：它只算"谁和谁相关"，<strong>天然不知道词的先后顺序</strong>。把"猫追狗"和"狗追猫"的词打乱输入，纯注意力会当成同一回事。所以在进模型前，要给每个 token 加一个<strong>座位号</strong>（位置编码），把"我是第几个词"的信息混进向量里。现代模型多用 RoPE（旋转位置编码）等方案。

#### 1.3.5 前馈网络与残差捷径

- <strong>FFN（前馈网络）</strong>：注意力负责 token 之间的信息聚合，FFN 负责对每个位置独立做非线性变换。部分研究发现某些事实关联可以在 FFN 中定位或编辑，但知识表征分布在嵌入、注意力和 FFN 等多处，不能简单理解为只存放在 FFN。
- <strong>残差连接</strong>：每层的输出 = 输入 + 本层的加工结果。相当于给信息留了一条"抄近道"的捷径，几十层堆叠时信号和梯度都能顺利通过，不至于传着传着就消失了。
- <strong>归一化（LayerNorm/RMSNorm）</strong>：把数值范围稳住，防止越算越炸。

#### 1.3.6 Decoder-only 与因果掩码

原始 Transformer 分编码器和解码器两部分；翻译模型是"编码器读原文 + 解码器写译文"。而 GPT 这类生成模型只用了解码器，叫 <strong>Decoder-only</strong> 结构，并且加了<strong>因果掩码</strong>：预测第 n 个词时只许看前 n-1 个词，不许偷看后面。

为什么？因为训练目标就是"猜下一个词"，如果能看到下一个词，就等于抄答案，什么都学不到。这个"只许看左边"的约束，恰好和接龙任务的形态完全一致，这也是 Decoder-only 成为主流的原因。

### 1.4 参数：模型的脑回路

所谓"7B 模型"，指它有 <strong>70 亿个参数</strong>，也就是 70 亿个可调节的浮点数（W_Q、W_K、W_V、FFN 权重等加起来）。

- <strong>推理</strong>：参数固定不动，输入一句话跑一遍前向传播，得到下一个词的分数。一次接龙只需毫秒级。
- <strong>训练</strong>：参数从随机数开始，不断被调整，直到模型"接得好"。这才是烧钱的部分。

::: tip

<strong>一句话类比：</strong> 架构是"大脑的沟回结构"（Transformer 怎么连），参数是"突触强度"（70 亿个旋钮的当前读数），训练是"调旋钮的过程"。同一个架构，拧到不同的参数值，就是不同的模型。

:::

### 1.5 温度与采样：接龙的方式

拿到概率分布后，怎么选词？永远选最高分的（贪心）会让回答死板重复；纯随机又容易蹦出怪词。实践用<strong>温度（temperature）+ 采样</strong>：

```python
import torch

logits = model(**inputs).logits[0, -1]          # 词表上每个词的分数

# 温度：除以 T 再 softmax。T 越小分布越"尖"，T 越大分布越"平"
probs = (logits / 0.8).softmax(dim=-1)

next_token = torch.multinomial(probs, num_samples=1)   # 按概率抽签
```

<table>
<tr><th>temperature</th><th>效果</th><th>适用场景</th></tr>
<tr><td>接近 0</td><td>几乎总选最高分，输出稳定</td><td>代码生成、信息抽取、数学</td></tr>
<tr><td>0.7 ~ 1.0</td><td>有随机性，自然多样</td><td>日常对话、文案写作</td></tr>
<tr><td>&gt; 1.2</td><td>过于发散，容易跑偏</td><td>头脑风暴（慎用）</td></tr>
</table>

这就是"同样的问题每次回答不一样"的原因：<strong>模型本身每次的打分几乎一样，差别只在最后抽签那一下</strong>。

## 第二章：预训练——把图书馆读进参数里

::: info

架构搭好了，参数还是一堆随机数——一个"刚出厂、啥都不会"的大脑。<strong>预训练（Pre-training）</strong>就是把这个大脑养成的第一步：用海量文本玩"猜下一个词"，一玩几个月。这一章讲清楚：目标、数据、过程、规律、产物和代价。

:::

---

### 2.1 训练目标：一个游戏玩几万亿次

预训练的损失函数只有一句话：<strong>让模型给真实的下一个 token 更高概率</strong>。训练时把同一段序列右移一位作为标签，并用因果掩码阻止当前位置看到未来 token；模型会同时对序列中的各个位置预测下一 token，预测越偏离标签，损失（loss）越大。

```python
# 伪代码：预训练的核心只有这几行
model = Transformer(params=random_init())        # 参数随机初始化
optimizer = AdamW(model.parameters(), lr=1e-4)   # 优化器 + 学习率（步子大小）

for batch in dataloader:          # 数据：几万亿 token，切成批次
    x, y = batch[:, :-1], batch[:, 1:]   # 输入: 前 n-1 个词；标签: 右移一位的答案

    logits = model(x)                    # 前向传播：猜每个位置的下一个词
    loss = cross_entropy(logits, y)      # 对答案：猜得越离谱，loss 越大

    optimizer.zero_grad()
    loss.backward()                      # 反向传播：算出每个参数该往哪拧、拧多少
    optimizer.step()                     # 拧旋钮：所有参数朝降低 loss 的方向微调

# 这几行循环几百万步，就是"预训练"
```

神奇之处在于：为了把"接龙"这一件事做好，模型<strong>被迫</strong>学会语法（不然接不通顺）、事实（"中国的首都是"后面接什么）、逻辑（推理链条）、代码（GitHub 上接注释和函数体）……所有能力都被压缩进参数里。

::: info

<strong>为什么"猜下一个词"这么有效：</strong> 要在海量语料上持续降低预测误差，模型必须学习语法、语义、事实关联和推理模式。至于这是否等同于人类意义上的"理解"仍有争论；可以确定的是，这个朴素目标能够产生广泛的可迁移能力。

:::

### 2.2 数据：几万亿词从哪来

```text
互联网原始数据（几十 TB：网页/书籍/论文/代码）
   ↓ 去重（相同、近似页面合并）
   ↓ 质量过滤（垃圾站、乱码、广告、低质内容）
   ↓ 安全处理（隐私信息、有害内容）
   ↓ 语料配比（网页 : 书籍 : 代码 : 论文 按比例混合）
高质量语料（几万亿 ~ 十几万亿 token）
   ↓
喂给模型玩"猜下一个词"
```

<table>
<tr><th>数据源</th><th>占比（典型）</th><th>主要贡献</th></tr>
<tr><td>网页（Common Crawl 等）</td><td>最大头</td><td>常识、口语、世界知识</td></tr>
<tr><td>书籍</td><td>中</td><td>长文连贯性、书面语、深度知识</td></tr>
<tr><td>代码（GitHub）</td><td>中</td><td>推理能力、代码生成能力</td></tr>
<tr><td>论文 / 百科 / 数学</td><td>小但精</td><td>专业知识、推理密度</td></tr>
</table>

::: warning

<strong>数据质量 > 数据数量：</strong> "Garbage In, Garbage Out"。预训练语料的清洗和配比是各家最核心的机密之一：同样的架构和算力，数据配比不同，最终能力可以差一大截。高质量数据的获取，已经成了预训练的主要瓶颈。

:::

### 2.3 训练过程：猜、对答案、拧旋钮

```text
        ┌──────────── 一个训练步 ────────────┐
        │                                    │
        │  取一批文本（一批几百万 token）        │
        │        ↓                           │
        │  前向传播：猜每个位置的下一个词         │
        │        ↓                           │
        │  对答案：算 loss（越差数字越大）        │
        │        ↓                           │
        │  反向传播：算每个参数的梯度            │
        │  （往哪拧、拧多少）                   │
        │        ↓                           │
        │  更新参数：所有旋钮微调一点点           │
        │        ↓                           │
        │  loss 降不动了？否 → 回到顶部         │
        └────────────────────────────────────┘

   几百万步 × 几千张 GPU × 几个月 = 一次预训练
```

训练过程中最常看的指标是 <strong>loss 曲线</strong>：一条从高位缓缓下降、逐渐趋平的曲线。loss 越低，说明模型在整个语料上"接龙"接得越准。训练中途存下来的存档叫 <strong>checkpoint</strong>（所以才有了后来泄露的各种"半成品模型"）。

### 2.4 Scaling Law：越大越聪明

2020 年 OpenAI 发表 Scaling Laws（Kaplan 等），2022 年 DeepMind 的 Chinchilla 论文修正了结论。核心经验规律：

> <strong>在相当大的范围内，参数越多、数据越多、算力越多，loss 就越低，模型就越聪明，且可以提前预测。</strong>

<table>
<tr><th>维度</th><th>含义</th><th>通俗说法</th></tr>
<tr><td>参数量</td><td>模型多大（7B / 70B / 405B…）</td><td>脑子多大</td></tr>
<tr><td>数据量</td><td>喂多少 token</td><td>读多少书</td></tr>
<tr><td>算力</td><td>总 FLOPs（GPU 数 × 时间）</td><td>上多少年学</td></tr>
</table>

Chinchilla 给出的经验结论：算力预算固定时，参数量和数据量应<strong>同比例增长</strong>（大约每个参数配 20 个 token）。这条规律直接决定了"砸多少钱 → 得到多聪明的模型"的投入产出预估，也是各家军备竞赛的理论依据。不过实践中（Llama 3 等）普遍会在同参数量下喂<strong>远超</strong> Chinchilla 最优值的数据：多读书总是更好，只是边际收益递减。

### 2.5 基座模型：博览群书的"怪才"

预训练的产物叫<strong>基座模型（Base Model）</strong>。它知识渊博，但有个尴尬的问题：<strong>它只学过"接龙"，没学过"当助手"</strong>。

```text
问基座模型: 中国的首都是哪里？

期待的回答:  中国的首都是北京。

基座模型:    中国的首都是哪里？这是小学地理考试中
            常见的题目之一。除此之外，中国的主要
            城市还有上海、广州、深圳……

（它不是在回答你，它是在"续写"——因为训练语料里
  问题后面往往还跟着别的问题和讲解文本）
```

<table>
<tr><th>能力</th><th>基座模型</th><th>说明</th></tr>
<tr><td>知识储备</td><td>✅ 强</td><td>几万亿 token 的知识都在参数里</td></tr>
<tr><td>语言流畅</td><td>✅ 强</td><td>接龙接了万亿次的语感</td></tr>
<tr><td>理解指令</td><td>❌ 弱</td><td>不知道"你要它当助手"，倾向续写而非回答</td></tr>
<tr><td>对话格式</td><td>❌ 无</td><td>不认识对话轮次，不会说"我是 AI"</td></tr>
<tr><td>拒绝与安全</td><td>❌ 无</td><td>没有对齐，有害请求照接不误</td></tr>
</table>

::: tip

<strong>生活化的比喻：</strong> 基座模型像一个把图书馆读完的书呆子——你问他问题，他可能接着你的话往下背书。要让他变成好同事，需要"岗前培训"。这就是第三章：后训练。

:::

### 2.6 预训练的门槛

- <strong>算力</strong>：旗舰模型需要数千到数万张顶级 GPU 连续跑数月，仅电费和硬件折旧就是数千万到数亿美元量级
- <strong>数据</strong>：高质量、去重、合规的万亿级 token 语料，工程量巨大
- <strong>工程</strong>：大规模分布式训练（数据/张量/流水线并行）、断点恢复、故障自愈，本身就是高门槛技术栈
- <strong>算法</strong>：MoE（混合专家）、长上下文扩展等架构决策，试错成本极高

所以全世界从头预训练旗舰模型的公司屈指可数，其余玩家都在开源基座（Llama、Qwen、DeepSeek 等）之上做后训练或应用。

## 第三章：后训练——从书呆子到好助手

::: info

预训练产出的基座模型通常还需要适配后才能成为好用的助手。<strong>后训练（Post-training）</strong>是在基座之上继续优化行为与能力的过程。本章先讲常见起点 SFT，再分别介绍两类偏好对齐方案（基于奖励模型与 PPO 的 RLHF、直接偏好优化 DPO），以及可按任务需要加入的 RLVR。它们不是必须全部串行执行的四个阶段。

贯穿本章的比喻：<strong>预训练 = 上学读书；SFT = 岗前培训；RLHF = 实习中被人点评；RLVR = 刷题练出打草稿的习惯。</strong>

:::

---

### 3.1 为什么基座模型不能直接用

回看 2.5 节的例子：你问"中国的首都是哪里？"，基座模型可能接一句"这是小学地理考试常见的题目"。差的不是知识，而是<strong>行为模式</strong>：

<table>
<tr><th>问题</th><th>基座的表现</th><th>期望的表现</th></tr>
<tr><td>角色意识</td><td>不知道自己是助手</td><td>以助手身份回答</td></tr>
<tr><td>回答方式</td><td>续写输入</td><td>先直接回答，再展开</td></tr>
<tr><td>不知道就说不知道</td><td>一本正经往下编</td><td>承认不确定</td></tr>
<tr><td>安全边界</td><td>有害请求照接</td><td>合理拒绝</td></tr>
</table>

后训练首先要解决这些行为问题：<strong>重点是教模型如何响应、如何取舍</strong>。它也可能注入领域知识或技能，但少量监督样本并不是稳定维护大量、时效性知识的理想方式。

### 3.2 SFT：照着范例学

<strong>SFT（Supervised Fine-Tuning，监督微调）</strong>是最直接的后训练：使用人工编写或模型生成并经筛选的"问题 → 理想回答"示范数据，继续用自回归交叉熵训练。它和预训练共享下一 token 预测形式，但数据分布、对话模板及损失掩码通常不同。

数据长这样（如今很多由强模型生成 + 人工校验）：

```json
[
  {
    "messages": [
      {"role": "user", "content": "中国的首都是哪里？"},
      {"role": "assistant", "content": "中国的首都是北京。"}
    ]
  },
  {
    "messages": [
      {"role": "user", "content": "帮我写一句下雨天的朋友圈"},
      {"role": "assistant", "content": "雨把城市调成了静音，我在窗边听它说话。"}
    ]
  }
]
```

训练前，这些对话会被渲染成模型认识的<strong>对话模板（chat template）</strong>：

```python
# 对话模板：把结构化对话渲染成一段带特殊标记的文本
prompt = tokenizer.apply_chat_template(messages, tokenize=False)
# <|im_start|>user
# 中国的首都是哪里？<|im_end|>
# <|im_start|>assistant
# 中国的首都是北京。<|im_end|>

# 关键细节：loss 只算 assistant 部分的 token
# —— 模型只学习"怎么答"，不用学习"怎么问"
```

::: info

<strong>SFT 主要塑造行为，也能影响知识与技能：</strong> 相比预训练语料，SFT 数据规模通常较小，最显著的作用是让模型学习助手角色、回答格式、任务步骤和安全示范。高质量领域数据也能补充能力或知识，但覆盖范围、遗忘和事实更新仍需单独评估。

:::

### 3.3 RLHF：根据反馈学分寸

SFT 有个天花板：示范数据只能教"什么是好的"，但<strong>好到什么程度、哪种更好，说不清楚</strong>。就像看教学视频学礼仪能学会基本动作，但分寸感要在实习中被点评才能磨出来，这就是 <strong>RLHF（Reinforcement Learning from Human Feedback，人类反馈强化学习）</strong>，也是 ChatGPT 走红的技术核心（InstructGPT 论文，2022）。

```text
          ┌────────────┐
          │  SFT 模型   │
          └─────┬──────┘
                │ 对同一个问题生成 4~9 个不同回答
                ▼
          ┌────────────┐
          │ 人类标注员   │  按有用/真实/安全排序（比直接打分容易）
          └─────┬──────┘
                │ 排序数据
                ▼
          ┌────────────┐
          │ 奖励模型 RM │  学会"给任意回答打分"
          └─────┬──────┘
                │ 分数当奖励信号
                ▼
          ┌────────────┐
          │ PPO 强化学习 │  模型朝高分方向调整参数
          └─────┬──────┘
                │ + KL 惩罚（不许偏离 SFT 模型太远）
                ▼
          对齐后的 Chat 模型
```

```python
# 伪代码：RLHF 的两个关键环节

# 环节 1：训练奖励模型 —— 排序数据转成两两成对
for question, chosen, rejected in preference_data:
    r_chosen = reward_model(question, chosen)      # 给"更好的回答"打分
    r_rejected = reward_model(question, rejected)  # 给"更差的回答"打分
    loss = -F.logsigmoid(r_chosen - r_rejected)    # 目标：好的分 > 差的分

# 环节 2：PPO —— 拿奖励当信号做强化学习
for question in prompt_data:
    response = policy_model.generate(question)     # 当前模型生成回答
    reward = reward_model(question, response)      # 奖励模型打分
    # KL 惩罚：离 SFT 模型太远就扣分，防止"为讨好 RM 而说怪话"
    loss = -(reward - beta * kl_divergence(policy_model, sft_model))
    loss.backward(); optimizer.step()
```

<table>
<tr><th>维度</th><th>SFT</th><th>RLHF</th></tr>
<tr><td>信号形式</td><td>"标准答案"（示范）</td><td>"哪个更好"（偏好）</td></tr>
<tr><td>学什么</td><td>格式、角色、套路</td><td>分寸感、 Helpful/Harmless 的权衡</td></tr>
<tr><td>比喻</td><td>岗前培训看手册</td><td>实习中被师傅点评</td></tr>
<tr><td>工程复杂度</td><td>低</td><td>高（4 个模型同框，显存与稳定性都有挑战）</td></tr>
</table>

::: warning

<strong>Reward Hacking（奖励投机）：</strong> 奖励模型只是人类偏好的近似。策略模型可能找到"让 RM 打高分但人觉得离谱"的输出，比如堆砌套话、过度冗长。KL 惩罚就是为压制这种漂移设计的，但无法根除。

:::

### 3.4 DPO：轻量级对齐

经典的奖励模型 + PPO 流程工程较重，训练时通常涉及策略模型、参考模型、奖励模型和价值函数。<strong>DPO（Direct Preference Optimization，直接偏好优化，2023）</strong>提供了另一条偏好对齐路线：直接从成对偏好数据优化策略，不显式训练奖励模型，也不运行 PPO。它通常是 PPO 式 RLHF 的替代选择，而不是其后的固定步骤。

```json
// DPO 数据：同一个问题的两个回答，人类标注谁更好
{
  "prompt": "如何学习编程？",
  "chosen":   "建议从一个小项目开始，边做边学。先定一个小目标……（详细、可执行）",
  "rejected": "编程很简单，随便学学就会了。（敷衍、无信息量）"
}
```

DPO 的损失直接比较两个回答的对数概率：让 `chosen` 的概率相对升高、`rejected` 的相对降低，数学上等价于一种隐式的奖励优化。

<table>
<tr><th>维度</th><th>RLHF（PPO）</th><th>DPO</th></tr>
<tr><td>需要奖励模型</td><td>需要（单独训练）</td><td>不需要</td></tr>
<tr><td>需要强化学习</td><td>需要（PPO，不稳定）</td><td>不需要（类似监督训练）</td></tr>
<tr><td>工程门槛</td><td>较高，包含在线采样与强化学习稳定性问题</td><td>较低，训练形态接近监督学习</td></tr>
<tr><td>效果特点</td><td>可利用在线采样持续探索，但更依赖奖励质量与训练稳定性</td><td>实现简单、稳定，效果取决于偏好数据覆盖和超参数</td></tr>
</table>

### 3.5 RLVR：学会打草稿

近年来后训练的重要方向之一，是在<strong>结果可以自动验证</strong>的任务上做强化学习，全称 RL with Verifiable Rewards（可验证奖励的强化学习）。

关键洞察：数学题可以核对答案、代码题可以跑单元测试，<strong>不需要人类标注"好不好"，对错机器自己知道</strong>。于是可以大规模地"刷题"：模型生成带推理过程的解答，对了给奖励，错了不给，能力就自己长出来了。

```text
┌────────────── RLVR 训练循环 ──────────────┐
│                                            │
│  出一道数学/编程题（有标准答案或测试用例）     │
│        ↓                                   │
│  模型生成完整解题过程（思维链 CoT）           │
│  "设未知数为 x……第一步……检查一下……"          │
│        ↓                                   │
│  机器自动判分：答案对 ✓ / 错 ✗ / 测试通过 ✓   │
│        ↓                                   │
│  强化学习：对的解题模式被强化，错的被抑制       │
│        ↓                                   │
│  模型逐渐学会：先打草稿、分步走、自我检查       │
└────────────────────────────────────────────┘

代表: OpenAI o1 (2024) · DeepSeek-R1 (2025)
```

DeepSeek 的 R1 论文记录了有趣的现象：R1-Zero 不以 SFT 冷启动，主要通过可验证奖励强化学习，训练中出现了更长的反思式推理轨迹，例如中途重新检查答案。这个实验说明，在特定模型、任务和奖励设计下，不提供人工推理过程示范也可能增强某些推理行为；它不能单独证明所有推理能力都会自然涌现。

::: info

<strong>推理模型 vs 常规模型：</strong> 推理模型会在回答前投入更多计算或生成更多中间 token，通常在数学、代码和复杂分析上更有优势，代价是延迟与成本增加。简单任务未必从额外推理中获益，应根据质量、时延和成本选择。

:::

### 3.6 完整流水线总览

```text
随机初始化的 Transformer（参数 = 一堆乱数）
        │
        ▼ 预训练：几万亿 token 上猜下一个词
        │ （几千卡 × 几个月 × 数千万美元级）
   基座模型 Base
   （知识丰富，但尚未稳定遵循指令）
        │
        ▼ SFT：几万~百万条「问-答」示范
        │ （学角色、格式、基本安全）
        ▼ 偏好对齐：RLHF（奖励模型 + PPO）或 DPO
        │ （两条常见替代路线，学习回答偏好与安全边界）
        ▼ （可选）RLVR：数学/代码刷题
        │ （学思维链：先打草稿再交卷）
   Chat / 推理 模型
   （你在产品里聊天的那个）
```

### 3.7 常见误区

::: danger

<strong>误区一："更新模型知识，只要做一次小规模微调。"</strong> 微调可以注入知识，但覆盖、可追溯性和更新稳定性往往不足。需要频繁更新或必须引用来源的知识优先用 RAG；需要改变广泛领域能力时，再评估继续预训练或较大规模微调。

:::

::: danger

<strong>误区二："Base 模型答错了，一定是没训练好。"</strong> Base 模型的任务本来就不是回答问题，而是续写。拿 Base 当 Chat 用，答非所问属于"正常发挥"。

:::

::: danger

<strong>误区三："RLHF 之后模型就不幻觉了。"</strong> 幻觉源于预训练目标本身：学的是"接得像"而不是"接得对"。后训练能压制（让模型更倾向说"我不确定"），不能根除。

:::

## 第四章：实践篇——训练之外的选择

前三章讲的是模型厂商的流水线。对应用开发者来说，更重要的问题是：<strong>我的需求该用哪种手段满足？</strong>大多数时候答案不是"训一个模型"，而是从最简单的方案开始，按需递进。

---

### 4.1 需求到方案决策树

```text
你的需求是什么？
│
├── 输出不够好 / 格式不对 / 不会拆解任务
│    └── → 优化 Prompt（角色设定、Few-shot、CoT）
│         成本最低，先试这个
│
├── 需要私有知识 / 实时数据
│    └── → RAG（检索增强）
│         知识外挂，改了文档立即生效，可溯源
│
├── 需要固定的风格 / 领域行为 / 输出格式
│    └── → 微调（LoRA）
│         几千~几万条数据，重点塑造"怎么干"，也可能补充领域能力
│
├── 需要全新领域 / 新语言的基础能力
│    └── → 继续预训练 CPT
│         在开源基座上灌大量领域语料"补课"
│
└── 不确定？从最简单的开始，按需递进
     Prompt → RAG → LoRA → CPT
```

::: tip

<strong>经验法则：</strong> 先用评测集定位问题，再按成本从 Prompt、工具调用或 RAG 开始验证。需要稳定改变输出格式、风格或领域行为时再考虑微调；知识类需求如果强调时效与可溯源，通常优先 RAG，但不存在适用于所有项目的固定比例。

:::

### 4.2 LoRA：轻量微调

全参数微调 7B 模型需要上百 GB 显存，普通团队玩不起。<strong>LoRA（Low-Rank Adaptation）</strong>的思路：冻结原模型全部参数，在旁边加一对小矩阵，只训小矩阵。

```text
原权重 W（d×d，冻结不动）
              │
              ├── 输出 += B·A    B: d×r  A: r×d   （r = 16，很小）
              │
效果: 可训练参数量 ≈ 原模型的 0.1% ~ 1%
      训练完可以只保存几十 MB 的"补丁"，
      同一个基座挂不同补丁 = 不同用途的模型
```

```python
from peft import LoraConfig, get_peft_model

config = LoraConfig(
    r=16,                                    # 秩：越小越省，16/32 常用
    lora_alpha=32,
    target_modules=["q_proj", "v_proj"],     # 只在注意力的部分投影上加
    task_type="CAUSAL_LM"
)
model = get_peft_model(base_model, config)
model.print_trainable_parameters()
# trainable params: 13M || all params: 7B || trainable%: 0.19%
```

<table>
<tr><th>维度</th><th>全参微调</th><th>LoRA</th></tr>
<tr><td>可训练参数</td><td>100%（7B）</td><td>0.1%~1%</td></tr>
<tr><td>显存需求</td><td>上百 GB（多卡）</td><td>单张消费级卡可跑（QLoRA 更省）</td></tr>
<tr><td>产物大小</td><td>完整模型（14 GB+）</td><td>几十 MB 补丁</td></tr>
<tr><td>效果上限</td><td>最高</td><td>绝大多数场景够用</td></tr>
</table>

### 4.3 蒸馏：大老师教小学生

<strong>知识蒸馏（Distillation）</strong>：用强模型的输出当训练数据，去教小模型。R1 论文的做法就是典型：用 R1 生成 80 万条高质量推理数据，SFT 教给小模型，让 7B 的小杯也学会打草稿。

- <strong>数据蒸馏</strong>（主流）：强模型生成"问题-答案"数据 → SFT 小模型
- <strong>logits 蒸馏</strong>（更学术）：小模型直接拟合强模型的输出概率分布

价值：在合适任务上显著降低推理成本。大模型当"老师"离线生成，小模型当"学生"在线服务；实际降幅取决于模型尺寸、硬件、吞吐和质量要求，不能保证固定为一个数量级。

### 4.4 术语小词典

<table>
<tr><th>术语</th><th>一句话解释</th></tr>
<tr><td><strong>Base / Chat / Instruct</strong></td><td>Base 主要按续写目标训练；Chat/Instruct 经过指令或对话后训练。面向终端对话通常选后者，研究、补充训练或特定续写任务可能选 Base</td></tr>
<tr><td><strong>Checkpoint</strong></td><td>训练过程中存下的参数快照，"存档"</td></tr>
<tr><td><strong>Loss</strong></td><td>模型"错得有多离谱"的数字，训练就是把它压下去</td></tr>
<tr><td><strong>Epoch / Step</strong></td><td>数据完整过一遍 / 每处理一个批次更新一次参数</td></tr>
<tr><td><strong>学习率 LR</strong></td><td>每次拧旋钮的幅度：太大震荡不收敛，太慢训不动</td></tr>
<tr><td><strong>上下文窗口</strong></td><td>模型一次能"看进去"的最大 token 数（4K~1M+）</td></tr>
<tr><td><strong>幻觉</strong></td><td>一本正经地编造，因为训练目标是"接得像"而非"接得对"</td></tr>
<tr><td><strong>对齐</strong></td><td>让模型行为符合人类意图和价值观（RLHF/DPO 做的事）</td></tr>
<tr><td><strong>思维链 CoT</strong></td><td>让模型"一步步想"的输出/提示方式，推理模型将其内化</td></tr>
<tr><td><strong>推理模型</strong></td><td>在回答时投入额外推理计算的模型；RLVR 是常见训练手段之一，但不是唯一实现路径</td></tr>
<tr><td><strong>MoE</strong></td><td>混合专家：每次只激活部分参数，大容量低推理成本</td></tr>
<tr><td><strong>量化</strong></td><td>把参数从 16bit 压到 4/8bit，模型变小变快，精度略降</td></tr>
</table>

## 总结：从随机参数到聊天伙伴

<table>
<tr><th>阶段</th><th>干什么</th><th>比喻</th><th>产物</th></tr>
<tr><td>架构 + 随机初始化</td><td>搭好 Transformer，参数是乱数</td><td>刚出厂的大脑</td><td>白纸一张</td></tr>
<tr><td>预训练</td><td>万亿 token 上猜下一个词</td><td>读万卷书</td><td>基座模型（会续写）</td></tr>
<tr><td>SFT</td><td>模仿「问-答」示范</td><td>岗前培训</td><td>会对话</td></tr>
<tr><td>RLHF / DPO</td><td>按人类偏好调整</td><td>实习被点评</td><td>有分寸、安全</td></tr>
<tr><td>RLVR</td><td>可验证任务上刷题</td><td>打草稿再交卷</td><td>推理模型</td></tr>
</table>

这些训练方法共享同一基座，但具体配方会按目标选择和组合：

- 推理模型再能打草稿，底层依然是那个只会"猜下一个词"的接龙机器
- 对话能力再自然，也建立在预训练灌进去的万亿 token 之上
- 再强的对齐，也压不住接龙目标的先天属性：幻觉只能管理，不能消灭

<strong>记住一句话就够了：架构是"大脑怎么连"，预训练是"读书养成知识"，后训练是"学着好好说话做事"。</strong>三者合起来，才是你面前这个能聊天的 AI。
