# 作者笔锋（author-voice）

本站文章的作者笔锋蒸馏。语料来源：《浅谈对于电商的业务理解》全文手写、《少年气与知天命》作者重写部分、以及一次完整的人机协作改稿 diff（AI 初稿 → 作者手改）。

**这是一个活资产，不是一次性蒸馏。** 每篇文章定稿后，把新句子和新改写对比回填进 `references/style_examples.md`，画像才会越用越准。

## 风格内核一句话

**一个在行业里泡了十年的人，把自己看到的门道掰开揉碎讲给你听，数据信手拈来，结论说得轻，顺带自嘲两句。**

## 笔锋卡

写之前过一遍，写完再对照一遍。

**词法**

- 惯用词：本质上、无非就是、大体、其实、也就、再者、同时、说人话就是。这些词出现是正常的，密度超了才是问题（基线见下）。
- 的/地混用是作者习惯（"时时刻刻的被评判"），不算错误，不要"纠正"。
- 口语拖尾可以有但要自然："坑啊包的""也就那么回事"，不能当补救手段堆。
- 箭头与数字直接写：`40 -> 35 -> 32 -> 28`、`600w家`、`平均6.3个人`。

**句法**

- 逗号长链一逗到底，不追求短句断节奏。长句是作者的天然流。
- 自问自答："我们的代价是什么呢，其实想想应该是没成本的。"
- "我们"视角而非"你"视角："我们在工作中多少都会接触到经验主义"。对读者说"你应该"立即变成说教。
- 俗语典故扔进去不解释：治大国如烹小鲜、光脚不怕穿鞋、日拱一卒、没有银弹、谋事在人成事在天。

**结构**

- 标题带类别前缀："客观成本 - 评判尺度上的潜在成本在变大"、"人性的难关之一 - 关于勇气"。
- 章间松过渡："上面两个讲了成本相关的部分，那么我们再讲一下……"
- 数据先行，结论淡出：先甩 600 万家工厂、6.3 个人的画像，再轻轻接一句"这个就比较符合实际情况了"。
- 金句进代码块卡片（``` 围栏），正文只陈述。正文段末不落格言。

**素材**

- 行业现实替外来理论：斩杀线、take rate、scaling law 涌现、评审会、与业务 battle。不引用读者没体感的学术框架。
- 生活细节敢进场：教育儿子"事情是做完的，不是磨完的"。
- 自嘲与坦白直接写："很惭愧，光进步技术去了""改下手写，大模型的AI感实在是太重了"。

**量化基线（tone_scan 对照作者手写语料得出）**

- 标记总密度 ≤ 1.8/千字（作者电商篇实测 1.8，少年气定稿 1.3）。
- "越……越" ≤ 0.3/千字；"本质上"属作者惯用词，1 处/千字内不管。
- 金句正文每节至多 1 处，多了进卡片或删。

## AI 角色边界

**AI 擅长（放心做）**：按作者已确定的角度扩写段落（必须先读本 skill 的句库当模板）；找行业数据和出处；梳理结构、查逻辑接缝；错别字与标点校对；tone_scan 与落点自检；构建、注册、提交等杂务。

**AI 做了会露馅（必须人来）**：第一手观察（评审会现场、斩杀线的体感）；核心观点的原创类比；家庭与生活细节；开头和结尾；金句。AI 起草这些内容时产出的名人例子、构造式比喻（"就像游泳说明书"）、理论引用（"多臂老虎机"）是本站已知的翻车点，改稿时优先识别替换。

## 工作流程

1. **起草前**：读 `references/style_examples.md`，按文章类型加载 `references/scenes/` 下对应场景（业务分析 / 随笔）。
2. **起草时**：AI 只写"擅长"清单内的部分，人写核心。AI 段落直接从句库里找同功能的真实例句仿写。
3. **定稿后**：跑 `de-ai-tone` 的 tone_scan 和落点自检（两者是配套的负面清单）。
4. **回填**：把这篇的新好句、以及"AI 初稿 vs 作者手改"的对比对追加进 `references/style_examples.md` 的对应分类。回填是本 skill 不"过期"的唯一手段。

## 边界

- 句库只从作者纯手写的语料抽，AI 起草后作者仅微调的文章不得入库（会污染基准）。目前可信语料：电商篇全文、少年气作者重写部分。
- 本 skill 管"像作者"，de-ai-tone 管"像人"，两个都要过。
- 排版规范（frontmatter、提示框、图片路径）以 AGENTS.md 和站内旧文为准，本 skill 不管。
